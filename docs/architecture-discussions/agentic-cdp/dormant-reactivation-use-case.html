Agentic CDP Use Case

沉睡会员唤醒与复购提升

每天找出 120 天以上未购、仍可触达、且有复购机会的会员，按价值、风险、偏好分层，生成差异化权益和内容，先创建可审计活动草案，再灰度执行和复盘。

定位

这个 use case 不应被设计成简单的“发券自动化”。它是一个跨 Data Agent、Process Agent、Governance、Measurement 的闭环：先找到值得唤醒的人，再判断是否允许触达，然后生成策略、内容、草案、审批包和复盘报告。
项目 定义
Scenario ID SCN_DORMANT_REACTIVATION
Primary Orchestrator ORCH_DORMANT_REACTIVATION
Trigger 每日 09:00 调度，或运营输入目标人群、预算、渠道和约束。
核心输出 segment_rule, campaign_brief, content_variants, approval_packet, execution_tasks, measurement_report
审批门槛 预算超过 50,000 或包含现金券时，需要 CRM Owner 审批。

Agent 分层

Orchestrator

ORCH_DORMANT_REACTIVATION

负责整体编排：确认目标、预算、约束、成功指标，调用 task agents，并最终产出场景计划、审批包和执行 trace。

Governance

TASK_CONSENT_POLICY_CHECK

在任何触达前检查 consent、退订、频控、预算和审批门槛。它是硬门禁，不是建议项。

Data Agent Platform

Agent 职责 输出
TASK_AUDIENCE_DISCOVERY 把“沉睡会员”转成可解释、可物化、可复跑的人群规则。 segment_spec, sql_condition, population_count, evidence
TASK_CHURN_RISK_SCORING 计算流失风险、沉睡原因和召回优先级，结合 RFM、消费、投诉和行为信号。 ranked_customer_list, reason codes
TASK_EFFECT_MEASUREMENT 衡量活动效果、归因收入、holdout 增量、异常和 agent 运行质量。 measurement_report, metric queries

Process Agent Platform

Agent 职责 输出
TASK_OFFER_OPTIMIZATION 在预算、毛利、权益等级和风险约束下生成优惠、补偿或权益策略。 offer_plan, budget impact, approval flag
TASK_CHANNEL_TIMING_SELECTION 选择短信、微信、邮件、导购跟进等渠道和触达时间，并做频控。 channel_plan, suppression list
TASK_CONTENT_GENERATION 生成多渠道文案、A/B 版本和导购话术，并执行合规检查。 content_variants, policy flags
TASK_CAMPAIGN_EXECUTION 创建活动草案、灰度执行计划和调度任务。第一版不直接发送。 campaign_draft, journey steps, schedule jobs

数据层

数据表 关键字段/用途
customers 会员画像、生命周期、days_since_purchase、orders_365、total_spend_365、rfm_segment、churn_risk_score、discount_affinity、preferred_channel。
transactions 最近购买时间、频次、金额、渠道、门店和活动归因。当前已注册为 agentic_cdp_transactions，可跑 RFM。
transaction_items 品类偏好、篮子结构、商品复购周期和推荐候选。
behavior_events 最近浏览、搜索、加购等弱意图信号，用于判断“沉睡但有兴趣”。
consents 营销、短信、微信、邮件许可。不可触达用户必须被拦截。
campaign_interactions 历史触达、转化、退订、suppression reason 和收入归因。
products 推荐商品、品类、价格、补货周期和 hero SKU。
service_tickets 投诉、负面情绪、SLA 和服务恢复信号。高服务风险用户不应直接营销。
必须区分“候选沉睡人群”和“可执行触达人群”。前者用于分析，后者必须通过 consent、频控、预算和风险检查。

指标层

输入诊断指标

  • 沉睡会员数：days_since_purchase >= 120
  • 可触达率：有 marketing/channel consent 的比例
  • 高价值沉睡数：高历史消费或高 LTV
  • 平均流失风险：MET_CHURN_RISK_AVG
  • 最近弱意图比例：沉睡但近期有浏览、搜索或加购
  • 历史活动疲劳：近期触达次数、退订、未响应次数

成功指标

  • MET_REACTIVATION_RATE：唤醒转化率
  • MET_INCREMENTAL_REVENUE：活动归因收入
  • 复购率、首单回流金额、AOV、毛利贡献
  • 渠道 CTR / CVR
  • 导购任务完成率

护栏指标

  • 退订率
  • 投诉率
  • policy block rate
  • 预算消耗
  • 低库存推荐阻断数
  • 频控拦截数

Agent 运行指标

  • latency
  • tool calls
  • eval score
  • human approval required
  • estimated cost USD

策略分层

人群 识别信号 建议策略
高价值高风险会员 历史消费高、VIP 分高、120 天以上未购、churn risk 高。 高优先级，导购或微信优先，权益更强；超预算或现金券进入审批。
有近期意图的沉睡会员 未购 120 天以上，但最近有浏览、搜索、加购。 推荐最近行为相关品类，轻权益，强调新品、库存、搭配。
折扣敏感会员 discount_affinity 高，历史促销响应好。 券或满减，但设置毛利底线和预算 cap。
品类周期复购会员 买过有补货周期的品类，当前接近或超过周期。 补货提醒和相关商品推荐，不做泛泛召回。
服务风险会员 近期投诉、负面 sentiment、未解决 ticket。 不直接营销，转服务恢复：补偿、客服或导购跟进、满意度修复。

执行流程

  1. Trigger: 每天 09:00 调度，或运营输入目标、预算、渠道和业务约束。
  2. Orchestrator 建立上下文: 生成 business_goal、预算、渠道范围、审批规则和成功指标。
  3. Audience Discovery: 查询候选人群，输出 segment_rule、population_count、样本用户和 SQL evidence。
  4. Consent & Policy Check: 过滤无许可、退订、频控冲突、投诉未解决或黑名单用户。
  5. Churn Risk Scoring: 用 RFM、沉睡天数、历史价值、投诉、弱意图和促销敏感度打分。
  6. Offer Optimization: 按 segment 分配权益，控制预算、毛利和审批门槛。
  7. Channel & Timing: 根据 preferred channel、consent、历史互动和频控输出触达计划。
  8. Content Generation: 生成微信、短信、邮件和导购话术，不暴露敏感推断。
  9. Campaign Execution: 第一版只创建 draft、journey steps、approval packet 和 schedule jobs。
  10. Measurement: 设置 holdout group，7/14/30 天复盘转化、收入、退订、投诉和渠道表现。

MVP 范围

第一版建议只做 dry-run artifacts，不真实发送：

ORCH_DORMANT_REACTIVATION → TASK_AUDIENCE_DISCOVERY → TASK_CONSENT_POLICY_CHECK → TASK_CHURN_RISK_SCORING → TASK_OFFER_OPTIMIZATION → TASK_CONTENT_GENERATION → TASK_CAMPAIGN_EXECUTION → TASK_EFFECT_MEASUREMENT

等策略、审批、指标和审计链路跑顺后，再接真实 MA/CRM connector。默认行为应是“创建草案”，不是“直接发送”。
